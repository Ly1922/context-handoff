# Context Handoff 协议

自动压缩会丢细节。`context-handoff` 插件会以 `[context-handoff]` 开头的系统消息提醒你，收到时：

- **要求写交接文件**：在下一个工具调用前，用 `write_file`（已存在就 `Overwrite=true` 整体重写）写入消息里给出的路径，然后继续原任务。不要向用户汇报这一步，也不要因此结束本轮。
- **刚压缩完**：先 `read_file` 读交接文件；如果它和压缩摘要冲突，以交接文件中更具体的内容为准，然后继续。
- 达成重要里程碑（方案定了、根因找到、大功能完成）时，也可以主动更新同一个文件。

交接文件写给一个“没看过本对话的同事”，要具体（路径、命令、数值、报错原文），总长不超过 150 行。不要写入密码、token、API key 原文，写“见 xxx 文件/环境变量”即可：

```markdown
# <任务标题>
## 目标 / 验收标准
## 当前状态（一句话）
## 已完成（含关键文件路径）
## 进行中 / 下一步（按顺序、可直接执行）
## 关键决策与原因
## 坑 / 已排除的方案
## 关键路径·命令·配置值
```

同目录下的 `*.auto.md` 是 hook 机械生成的快照（用户请求、改过的文件、命令），只读不改。
